## Standalone Go migration

- Added native Kugou and Qishui adapters and expanded QQ Music support to Personal FM, QRC lyrics, QR login, and renewal with the saved device identity.
- Added Qishui signed playback and an audio proxy with Range support. The admin QR and verification flows can use Chromium and the existing security SDK.
- Expanded native administration to four-platform credentials, API tokens, users and roles, shared accounts, monitoring, webhooks, and backups.
- Added support for existing Node v3.4.4 scrypt administrator records and retained import of older records.
- Matched QQ playback request formatting and quality labels, tried eligible SVIP accounts before lowering QQ quality, and restored the credential-free Kugou fallback.

## Compatibility and verification

The mock contract checks compare the migrated flows with Node v3.4.4. They cover QR session confirmation, four-platform account playback, QQ renewal, Qishui secondary verification, and the Kugou authorization chain and fallback. Real member playback and provider challenge completion depend on the deployment's accounts and upstream services and were outside this release check.

The native admin uses an HttpOnly session cookie and CSRF protection. The compatibility image retains the original Node admin session contract for clients that still use it.

See the [Node-to-Go migration guide](https://github.com/nova1751/openmusic-meting-api-go/blob/v0.3.0/docs/MIGRATE_NODE_TO_GO.md) for configuration and rollback. Release assets include executables for Linux, macOS, and Windows on amd64 and arm64, Linux Docker archives for both architectures, and checksums.
